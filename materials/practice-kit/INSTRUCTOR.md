# Подготовка и ручное сопровождение практики

[Комплект](README.md) · [Программа](../../curriculum.md) · [Протокол авторской проверки](VALIDATION.md)

## До первого занятия

1. Уточните открытые вопросы AGENTS.md: команда/график, приоритет, данные/права, API/.NET/IdP, модели/registry, ИБ/retention, эксперты, нагрузка. Пока их нет, используйте только синтетический автономный путь.
2. Полностью выполните «образ → модель → inference → API → оценка» на **эталонной RTX 3060 12 ГБ**, затем backward/optimizer/serving адаптера и VLM на граничных длинах. Сохраните версии, память, время, лицензии, русский язык и полезный контекст. Местная RTX 5060 Ti не заменяет эту проверку.
3. Подготовьте образы, snapshots, offline files/registry, пакеты и дисковое место. Выдайте готовые endpoints для П1.1: модуль 1 использует сервис до изучения его развёртывания в модуле 2. Загрузка моделей не оплачивается скрытыми часами самостоятельной работы.
4. Заранее подготовьте облачную синтетическую песочницу П1.1, допуски/ключи и лимиты. Без реального облачного прогона этот пункт не считается выполненным.
5. Проверьте UID/GID и permissions учебного secret volume; для предприятия назначьте настоящий provider и план expiry/revoke/rotation. Не храните секреты в model context, исходниках и audit.
6. Просмотрите все синтетические эталоны как предметный эксперт. Подготовьте новые документные семьи, настоящую разрешённую рукопись/шаблоны/чертежи для промышленной ветки; генератор их не имитирует полноценно.

## Независимость оценки и эталоны

Публичные данные, labels и решения лежат вместе по запросу пользователя. Они подходят для обучения/регрессии, но не скрытого тестирования. Назначьте хранителя test, подготовьте новый разрешённый набор до занятия, закрепите manifest и выдайте входы без эталонов только после фиксации вариантов/порогов. Test-ответы/labels не индексируются и не используются для синтетики/negative mining. Для RAG заранее задайте разрешённую границу корпуса.

Самостоятельный участник может выполнить все технические шаги, но финальное независимое review должно провести другое лицо. Если группы нет, назначьте коллегу/преподавателя; отсутствие второго исполнителя фиксируется как невыполненная независимая часть. Не заменяйте его собственным повтором или LLM-судьёй.

## Часовой бюджет и зависимости

Работы сохраняют 40 ID и 112 часов из curriculum.md; задания дают поминутные ориентиры, суммирующиеся в исходные часы. Крупные данные/доступы/образы готовит организатор до сессии. Capstone строится из накопленных компонентов, а не заново за пять часов. Не вводите новые обязательные часы под видом домашней установки.

На каждую работу предусмотрены вводный разбор, самостоятельная реализация/измерение, негативные случаи и ручная сверка. Группа инженеров Python/SQL знакомится с C# через небольшой net8.0-проект; неизвестная версия предприятия остаётся отдельной зависимостью. Обязательный QLoRA-эксперимент можно выполнить на маленькой согласованной модели; fine-tuning в capstone не обязателен.

Планируйте экспертный ресурс по числу объектов и времени проверки: исходная разметка, независимое перекрытие/разногласия, калибровка, synthetic review, hard negatives, critical fields и финальная приёмка. Фиксированного окна «2–3 дня» без расчёта нет.

## Ручная приёмка

Пользователь исключил автоматическую проверку сдаваемых работ. Здесь нет LMS/grader/автоматического зачёта. Скрипты рассчитывают метрики и проверяют поведение эталонного кода, как требует инженерная методика; результат работы оценивается человеком по программе и [review sheet](templates/review.md).

Для каждого критерия требуйте артефакт/наблюдение. Сохраняйте три исхода: выполнено, исправить, недостаточно данных. Корректный отрицательный эксперимент принимается; критичный ACL/secret/production-write/test-contamination блокирует приёмку независимо от среднего качества. Исправления и повторное review разрешены, вклад участников фиксируется.

Не требуйте совпадения с одной формулировкой эталона или одинакового времени на разной GPU. Нужны контракт, источник, эффект, честная методика и границы вывода. LLM-as-judge не заменяет эксперта для критичных сценариев.

## Автономная и корпоративная ветки

Автономный комплект позволяет исполнять методику без доступов предприятия. При переносе отдельно подтвердите:

- настоящие auth/минимальные права/secret lifecycle .NET API;
- семантику схем/единиц/NULL, права views и лимиты реальной БД;
- ACL/cache/history/direct links/revocations для корпоративного поиска;
- качество OCR/VLM на разрешённых сканах/рукописи/чертежах и 12 ГБ;
- настоящий target/legacy/build/CI/code licenses;
- профиль нагрузки, аудит/retention, офлайн-комплект, rollback/restore;
- независимый test, baseline процесса, стоимость и подтверждённых владельцев.

Не записывайте недоступную корпоративную часть как пройденную по результату синтетического аналога. Учебный go означает следующий ограниченный этап. При no-go сохраните доказательства, условия пересмотра и план на 3–6 месяцев.
