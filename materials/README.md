# Учебные материалы курса

Материалы предназначены для инженеров, знакомых с Python, SQL и процессами PDM/ERP/MES. Теория и практика связаны одним промышленным учебным кейсом. Основной источник структуры, часов и критериев — [программа курса](../curriculum.md).

## Как пользоваться материалами

В `README.md` каждого модуля находятся цели, связь теории с практикой и навигация. В `self-study.md` — полный теоретический конспект: маршрут чтения, объяснения, разобранные примеры в Markdown, вопросы с ответами и открытые источники. Этот же конспект используется для коротких вводных и обсуждений на контактных занятиях.

Маршруты самостоятельного изучения занимают **38 академических часов**, один академический час — 45 минут. Они включают чтение выбранных частей источников, разбор примеров и самопроверку. Полное чтение статей и документации из разделов дополнительного чтения необязательно. Оставшиеся **112 часов** — контактная практика со встроенной теорией; новые лекционные часы не добавлены, общий объём — **150 часов**.

Все **40 практических работ** наполнены: исходные данные, самостоятельный маршрут, негативные сценарии, критерии и артефакты. В `solutions/` каждого модуля доступны отдельные разобранные эталоны. Начните с [практического комплекта](practice-kit/README.md): Docker-стенды, синтетические данные, исполняемый код, шаблоны отчёта и ручного review. Организатор использует [инструкцию подготовки](practice-kit/INSTRUCTOR.md), фактические проверки описаны в [протоколе](practice-kit/VALIDATION.md).

Автоматической проверки/оценивания сдаваемых работ нет: скрипты помогают измерять поведение, а результат принимает человек. Эталон открывают после собственной попытки. Публичные данные и ответы подходят для отладки/регрессии; финальную независимую проверку готовит коллега/преподаватель на новых группах. Вопросы самопроверки теории не добавляют работ или часов.

## Сквозные правила чтения примеров

Результаты технического и методического [ревью курса](REVIEW.md) содержат перечень исправлений и границы выполненной проверки. Они дополняют протокол запусков учебного комплекта.

- Все предметные значения и идентификаторы в коде синтетические. Промышленные данные обрабатываются только on-prem; облачная учебная песочница допускает лишь явно разрешённые данные.
- Самодостаточные примеры Python используют стандартную библиотеку, кроме явно обозначенных фрагментов Pydantic и Transformers/PEFT. У C#, SQL, YAML и shell-фрагментов рядом указаны предпосылки. Конфигурационный фрагмент с заполнителями не является готовым стендом.
- Модели, серверы и библиотеки приведены как примеры классов решений. Их ревизии, лицензии, совместимость с Windows 11/WSL2/Docker и RTX 3060 12 ГБ закрепляются после preflight. Наличие примера не обещает соответствия неизвестной инфраструктуре предприятия.
- Проверка формы ответа не доказывает смысл; среднее качество не заменяет проверку критичных ошибок, прав и отказов. Любая write-операция курса ограничена тестовым контуром, предпросмотром и явным подтверждением человека.

Открытые источники — документация разработчиков, исходные статьи и методические материалы. Ссылки просмотрены при подготовке 4 ноября 2026 года; страницы `latest`, `current`, `stable` и ветки `master` могут меняться. Перед проведением курса организатор сохраняет согласованные версии для офлайн-среды. Открытие публичной документации не даёт разрешения отправлять в её интерактивные сервисы документы предприятия.

## Краткий словарь

| Термин | Значение в курсе |
|---|---|
| Baseline | Сопоставимый текущий или более простой способ решения |
| Inference / serving | Вычисление ответа модели / предоставление модели как сервиса |
| Retrieval / RAG | Поиск источников / генерация с извлечённым контекстом |
| Abstention | Отказ от содержательного ответа при недостаточности оснований |
| Provenance | Прослеживаемое происхождение значения и его преобразований |
| ACL / HITL | Правила доступа / включение человека в контур решения |
| Fine-tuning / SFT / LoRA | Изменение весов / обучение на желательных ответах / обучение низкоранговых поправок |
| Regression / quality gate | Проверка сохранения свойств / правило допуска версии |
| Rollout / rollback / restore | Выпуск / возврат согласованной версии / восстановление состояния из копии |
| Go/no-go | Обоснованное решение о следующем этапе или остановке |
