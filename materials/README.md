# Учебные материалы курса

Материалы предназначены для инженеров, знакомых с Python, SQL и процессами PDM/ERP/MES. Теория и практика связаны сквозными учебными сценариями из промышленной предметной области. Основной источник сведений о структуре, часах и критериях — [программа курса](../curriculum.md).

## Как пользоваться материалами

В `README.md` каждого модуля указаны цели, объяснена связь теории с практикой и приведены ссылки на материалы. В `self-study.md` находится основной теоретический конспект: маршрут чтения, объяснения, разобранные примеры в Markdown, вопросы с ответами и ссылки на открытые источники. Этот же конспект используется для коротких вводных блоков и обсуждений на контактных занятиях.

Маршруты самостоятельного изучения занимают **38 академических часов**; один академический час равен 45 минутам. Они включают чтение выбранных частей источников, разбор примеров и самопроверку. Полное чтение статей и документации из разделов дополнительного чтения необязательно. Оставшиеся **112 академических часов** — контактная практика со встроенной теорией. Отдельные лекционные часы не предусмотрены; общий объём — **150 академических часов**.

Для всех **40 практических работ** подготовлены исходные данные, последовательность самостоятельного выполнения, негативные сценарии, критерии приёмки и перечень сдаваемых материалов. В `solutions/` каждого модуля доступны отдельные разборы эталонных решений. Начните с [практического комплекта](practice-kit/README.md): он содержит Docker-стенды, синтетические данные, исполняемый код, шаблоны отчёта и ручной проверки. Организатор использует [инструкцию подготовки](practice-kit/INSTRUCTOR.md); фактически выполненные проверки описаны в [протоколе](practice-kit/VALIDATION.md).

Автоматического оценивания сдаваемых работ нет: скрипты помогают измерять поведение системы, а результат принимает человек. Эталон открывают после собственной попытки. Публичные данные и ответы подходят для отладки и регрессионных проверок; финальную независимую проверку на новых группах примеров готовит коллега или преподаватель. Вопросы для самопроверки входят в теоретическую подготовку и не добавляют отдельных работ или часов.

## Сквозные правила чтения примеров

В отчёте о техническом и методическом [ревью курса](REVIEW.md) перечислены исправления и границы выполненной проверки. Он дополняет протокол запусков учебного комплекта.

- Все предметные значения и идентификаторы в коде синтетические. Промышленные данные обрабатываются только on-prem; облачная учебная песочница допускает лишь явно разрешённые данные.
- Самодостаточные примеры Python используют стандартную библиотеку, кроме явно обозначенных фрагментов Pydantic и Transformers/PEFT. Для фрагментов на C#, SQL, YAML и shell рядом указаны условия запуска. Конфигурационный фрагмент с заполнителями не является готовым стендом.
- Модели, серверы и библиотеки приведены как примеры классов решений. Их ревизии, лицензии, совместимость с Windows 11/WSL2/Docker и RTX 3060 12 ГБ закрепляются после preflight. Наличие примера не гарантирует совместимости с инфраструктурой предприятия.
- Проверка формы ответа не подтверждает правильность его содержания; среднее качество не заменяет проверку критичных ошибок, прав и отказов. Любая write-операция курса ограничена тестовым контуром, предпросмотром и явным подтверждением человека.

Открытые источники — документация разработчиков, исходные статьи и методические материалы. Материалы по ссылкам просмотрены при подготовке 4 ноября 2026 года; страницы `latest`, `current`, `stable` и ветки `master` могут меняться. Перед проведением курса организатор сохраняет согласованные версии для офлайн-среды. Открытие публичной документации не даёт разрешения отправлять в её интерактивные сервисы документы предприятия.

## Краткий словарь

| Термин | Значение в курсе |
|---|---|
| Baseline | Текущий или более простой способ решения, с которым сравнивают результат на сопоставимых случаях |
| Inference / serving | Получение ответа модели / предоставление модели как сервиса |
| Retrieval / RAG | Поиск источников / генерация ответа с использованием найденных фрагментов |
| Chunking / reranking | Разбиение документов на фрагменты / повторное ранжирование найденных кандидатов |
| Abstention | Отказ от содержательного ответа при недостаточности оснований |
| Provenance | Прослеживаемое происхождение значения и его преобразований |
| ACL | Список правил доступа к объекту; используется для ограничения доступных пользователю данных |
| HITL | Участие человека в обработке и принятии решения по заданным правилам |
| Fine-tuning / SFT / LoRA | Дообучение модели / дообучение с учителем на желаемых ответах / обучение низкоранговых поправок к весам |
| Regression / regression testing | Ухудшение ранее подтверждённых свойств / проверки, выявляющие такие ухудшения |
| Quality gate | Заранее заданное правило допуска версии по результатам проверок |
| Rollout / rollback / restore | Развёртывание новой версии / возврат согласованного комплекта версий / восстановление состояния из копии |
| Go/no-go | Обоснованное решение о следующем этапе или остановке |
