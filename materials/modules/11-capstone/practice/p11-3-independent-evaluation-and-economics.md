# П11.3. Независимая оценка и экономика

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 2 ак. ч. (90 минут). Работа обязательна на базовом уровне. Подготовка — 15 мин; реализация/эксперимент — 40; негативные случаи — 25; анализ и оформление — 10. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Провести независимое сравнение с процессом и оценить полную стоимость проверенного результата.

## Перед началом

П11.1–П11.2; теория 11, разделы 3–5. Финальный test ещё не использовался для настройки.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p11-3-independent-evaluation-and-economics/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

Паспорт/пороги, test хранителя, baseline времени, результаты quality/load/HITL и исходные экономические допущения.

## Порядок самостоятельного выполнения

1. Независимый участник проверяет методику: provenance/split/dedup, baseline, отсутствие test tuning, знаменатели ошибок, правила экспертизы и версии. Затем открывает/исполняет финальный набор.

2. Соберите качество по срезам, critical violations, P95/ресурсы, активное время специалиста/цикла, ручную долю и переделки на сопоставимых случаях. Не исключайте отказы.

3. Рассчитайте разовые и регулярные затраты: разметка/эксперты, разработка/интеграция, инфраструктура/inference, ручная проверка, update/regression/support и изменение потерь от ошибок.

4. Постройте осторожный/базовый/благоприятный сценарии по потоку, времени review и реализации экономии. Избегайте двойного счёта одной и той же экономии труда.

5. Независимый reviewer подтверждает или оспаривает вывод. Примите go к следующему ограниченному этапу либо no-go с доказательствами; при недостаточной выборке используйте insufficient evidence и план получения данных.

## Команды для воспроизводимого старта

```powershell
docker compose run --rm lab python scripts/demo.py economics
```

Команды запускают эталонные компоненты/измерения. Скопируйте результаты из `work/` в каталог своего прогона до повторного запуска. Это инженерная проверка поведения, а не автоматическая сдача задания.

## Негативные случаи

Цена считается только по токенам; saved_minutes не учитывает review; быстрые отказы выданы за throughput; синтетические цифры названы прогнозом предприятия.

## Самопроверка и критерии приёмки

независимая команда/эксперт подтверждает методику; измерены качество, P95 latency, ресурсы, время специалиста, ручная проверка и полная стоимость, включая разметку и поддержку; представлено подтверждённое преимущество либо честное no-go с доказательствами.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

## Что представить для сверки

independent-review.md, test rows/срезы, process comparison, cost model с формулами/источниками/чувствительностью и решение.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

Коэффициент реализации экономии должен иметь бизнес-основание. Положительный net не компенсирует недопустимый риск. Если baseline не измерен, экономический go не доказан.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.

## Эталон после собственной попытки

[Разобранное эталонное решение](../solutions/p11-3-independent-evaluation-and-economics.md) позволяет сверить поведение и доказательства. Открытые данные/ответы не являются независимым test; финальные новые случаи готовит и хранит коллега/преподаватель. Корректный отрицательный эксперимент может быть принят.
