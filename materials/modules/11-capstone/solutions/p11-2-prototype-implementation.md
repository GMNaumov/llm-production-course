# Эталон П11.2. Сборка прототипа

[Задание](../practice/p11-2-prototype-implementation.md) · [Теория](../self-study.md) · [Правила сверки](../../../practice-kit/README.md)

Эталон показывает один корректный вариант и границы вывода. Сначала выполните собственную попытку; затем сравните поведение, методику и причины расхождений. Код и таблицы не оценивают работу участника автоматически.

## Разбор решения

Эталон прототипа RAG — Compose inference+gateway, заданный корпус A, поиск/генерация с исходными ссылками, draft/review и audit. Для более простого пилота search без генерации допустим при выполнении паспорта; fine-tuning необязателен.

Протокол другой команды содержит среду, checksums, команды, первый результат, негативные случаи, скрытые зависимости и итог. Работа не завершает независимую часть, пока запуск другого исполнителя не выполнен.

## Как сравнить собственный результат

1. Сопоставьте артефакты с каждым критерием [программы](../../../../curriculum.md) и задания. Укажите доказательство.
2. Разберите хотя бы одно расхождение: методика, набор/версия, ошибка кода, неопределённость или ожидание. Не подгоняйте финальный test под эталон.
3. Подтвердите негативные случаи: Демо работает только с cache автора; секрет в Compose; ACL фильтруется после генерации; dependency error возвращает выдуманный ответ; confirm делает модель.
4. Зафиксируйте ограничения: Самостоятельное прохождение возможно до передачи на независимое review. Если второй команды нет, нужен коллега/преподаватель; собственный повтор не записывают как независимый.
5. Передайте отчёт на ручное review. При одиночном прохождении независимая проверка остаётся ожидающей коллегу/преподавателя; собственная сверка её не заменяет.

## Контрольный вопрос

Что считать скрытой зависимостью, если коллеге для запуска понадобился ваш домашний каталог?

Итог — аргументированное решение на измеренных данных. Latency/VRAM/стоимость зависят от среды и состава случаев; открытые синтетические результаты не обещают качество предприятия.
