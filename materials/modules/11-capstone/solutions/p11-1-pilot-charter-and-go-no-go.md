# Эталон П11.1. Паспорт пилота и критерии go/no-go

[Задание](../practice/p11-1-pilot-charter-and-go-no-go.md) · [Теория](../self-study.md) · [Правила сверки](../../../practice-kit/README.md)

Эталон показывает один корректный вариант и границы вывода. Сначала выполните собственную попытку; затем сравните поведение, методику и причины расхождений. Код и таблицы не оценивают работу участника автоматически.

## Разбор решения

Эталон доступного capstone: «Инженер A задаёт вопрос о выпуске; получает действующую редакцию с цитатой или отказ; сравниваем полное время поиска с проверкой источника». Scope: локальная синтетика, read-only, без production и без автоматического решения.

В паспорте есть метрика/порог/основание/владелец/тест для каждого критерия. Конкретные числа назначают учебные владельцы до финального прогона; неизвестные параметры предприятия перечисляются как зависимости, не заполняются вымыслом.

## Как сравнить собственный результат

1. Сопоставьте артефакты с каждым критерием [программы](../../../../curriculum.md) и задания. Укажите доказательство.
2. Разберите хотя бы одно расхождение: методика, набор/версия, ошибка кода, неопределённость или ожидание. Не подгоняйте финальный test под эталон.
3. Подтвердите негативные случаи: Паспорт «сделать production-ready ассистента», неподтверждённый baseline, test доступен автору для настройки, никто не владеет update/rollback.
4. Зафиксируйте ограничения: Capstone — интеграция накопленных компонентов, не новый проект с нуля за 5 часов. При недоступности эксперта независимая приёмка остаётся незавершённой.
5. Передайте отчёт на ручное review. При одиночном прохождении независимая проверка остаётся ожидающей коллегу/преподавателя; собственная сверка её не заменяет.

## Контрольный вопрос

Что нужно зафиксировать до capstone, чтобы отрицательный результат тоже можно было принять?

Итог — аргументированное решение на измеренных данных. Latency/VRAM/стоимость зависят от среды и состава случаев; открытые синтетические результаты не обещают качество предприятия.
