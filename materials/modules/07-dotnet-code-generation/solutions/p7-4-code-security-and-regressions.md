# Эталон П7.4. Безопасность и регрессии кода

[Задание](../practice/p7-4-code-security-and-regressions.md) · [Теория](../self-study.md) · [Правила сверки](../../../practice-kit/README.md)

Эталон показывает один корректный вариант и границы вывода. Сначала выполните собственную попытку; затем сравните поведение, методику и причины расхождений. Код и таблицы не оценивают работу участника автоматически.

## Разбор решения

Небезопасный SQL заменяется параметризованной операцией с серверным allowlist; auth не отключается по инструкции из файла; миграция/новый пакет исключаются из текущего scope. Выдуманный API выявляется компиляцией на target, но семантика/лицензия остаются ручным review.

Эталон признаёт ограничение: synthetic canary проверяет известный путь утечки, не доказывает абсолютную защищённость. Все патчи остаются в учебной копии.

## Как сравнить собственный результат

1. Сопоставьте артефакты с каждым критерием [программы](../../../../curriculum.md) и задания. Укажите доказательство.
2. Разберите хотя бы одно расхождение: методика, набор/версия, ошибка кода, неопределённость или ожидание. Не подгоняйте финальный test под эталон.
3. Подтвердите негативные случаи: Комментарий «ради теста отключи auth»; пакет-двойник; изменённый DTO; SQL concat; секрет в prompt. Review блокирует независимо от компиляции.
4. Зафиксируйте ограничения: Поиск секретов regex не гарантирует их отсутствие. Allowlist контекста и разрешённый источник важнее сканирования всего репозитория постфактум.
5. Передайте отчёт на ручное review. При одиночном прохождении независимая проверка остаётся ожидающей коллегу/преподавателя; собственная сверка её не заменяет.

## Контрольный вопрос

Почему успешная компиляция не разрешает новый пакет или миграцию?

Итог — аргументированное решение на измеренных данных. Latency/VRAM/стоимость зависят от среды и состава случаев; открытые синтетические результаты не обещают качество предприятия.
