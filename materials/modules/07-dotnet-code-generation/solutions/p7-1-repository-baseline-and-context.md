# Эталон П7.1. Baseline репозитория и контекст

[Задание](../practice/p7-1-repository-baseline-and-context.md) · [Теория](../self-study.md) · [Правила сверки](../../../practice-kit/README.md)

Эталон показывает один корректный вариант и границы вывода. Сначала выполните собственную попытку; затем сравните поведение, методику и причины расхождений. Код и таблицы не оценивают работу участника автоматически.

## Разбор решения

Штатные исходные результаты: 10−4=6, 0−0=0, 1,5−0,5=1. Они не обнаруживают отрицательные входы и completed>ordered. Эталон контекста включает только QuantityRules.cs, Program.cs, csproj и согласованное требование.

Нет внешних пакетов, NuGet.Config очищает feeds; сборка воспроизводится установленным SDK net8.0. Для enterprise-репозитория нужно отдельно закрепить SDK/lock/CI и старые ошибки.

## Как сравнить собственный результат

1. Сопоставьте артефакты с каждым критерием [программы](../../../../curriculum.md) и задания. Укажите доказательство.
2. Разберите хотя бы одно расхождение: методика, набор/версия, ошибка кода, неопределённость или ожидание. Не подгоняйте финальный test под эталон.
3. Подтвердите негативные случаи: Исходный build уже падает; найден старый интерфейс в bin; контекст содержит токен; комментарий предлагает изменить auth. Ошибки baseline фиксируются до генерации.
4. Зафиксируйте ограничения: Сборка репозитория может исполнять MSBuild targets. Используйте доверенный учебный проект и изоляцию с сетью по согласованной политике; доступ production не нужен.
5. Передайте отчёт на ручное review. При одиночном прохождении независимая проверка остаётся ожидающей коллегу/преподавателя; собственная сверка её не заменяет.

## Контрольный вопрос

Почему успешная исходная сборка не доказывает полноту исходных тестов?

Итог — аргументированное решение на измеренных данных. Latency/VRAM/стоимость зависят от среды и состава случаев; открытые синтетические результаты не обещают качество предприятия.
