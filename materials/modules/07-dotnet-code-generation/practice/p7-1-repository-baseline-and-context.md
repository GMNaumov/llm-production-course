# П7.1. Baseline репозитория и контекст

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 2 ак. ч. (90 минут). Работа обязательна на базовом уровне. Подготовка — 15 мин; реализация/эксперимент — 40; негативные случаи — 25; анализ и оформление — 10. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Зафиксировать исходный C#-репозиторий и собрать минимально достаточный безопасный контекст.

## Перед началом

Теория 7, разделы 1–3. Для автономного маршрута используйте `dotnet/Quantity`; корпоративный разрешённый репозиторий подключается после выдачи.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p7-1-repository-baseline-and-context/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

QuantityRules.Remaining с намеренно отсутствующей проверкой границ, Program.cs с тремя штатными наблюдениями; современный net8.0, без внешних NuGet-пакетов.

## Порядок самостоятельного выполнения

1. Скопируйте учебный проект в `work/p7-1/repo`, сохранив исходный snapshot/commit. Прочитайте csproj, NuGet.Config, target framework, анализаторы и правила задачи. Не подменяйте современный net8 legacy-версией компании.

2. В изолированном SDK выполните restore/build/существующие проверки до генерации. Запишите SDK и warnings. Три штатных примера проходят, но не проверяют отрицательные границы — это пробел baseline, а не доказательство корректности.

3. Опишите публичный контракт: decimal, сигнатура Remaining, ordered/completed неотрицательны, completed≤ordered, исключения по именам параметров. Согласуйте требование до патча.

4. Соберите allowlist контекста: задача, csproj, QuantityRules, вызывающий код, релевантные проверки. Исключите bin/obj, секреты и unrelated файлы. Для реального репозитория покажите поиск символов/зависимостей.

5. Добавьте в отдельный недоверенный файл синтетическую injection, предлагающую удалить проверки. Проверьте, что содержимое файла не меняет полномочия/критерии. Сохраните список выбранных файлов и основание каждого.

## Негативные случаи

Исходный build уже падает; найден старый интерфейс в bin; контекст содержит токен; комментарий предлагает изменить auth. Ошибки baseline фиксируются до генерации.

## Самопроверка и критерии приёмки

до генерации зафиксированы сборка, тесты, анализаторы и исходные ошибки; модель получает только разрешённые файлы без секретов; проверено, что найденные файлы относятся к задаче и публичные контракты известны.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

Почему успешная исходная сборка не доказывает полноту исходных тестов?

## Что представить для сверки

baseline snapshot/SDK/build/checks, контракт, allowlist/context bundle без секретов и критерии патча.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

Сборка репозитория может исполнять MSBuild targets. Используйте доверенный учебный проект и изоляцию с сетью по согласованной политике; доступ production не нужен.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.

## Эталон после собственной попытки

[Разобранное эталонное решение](../solutions/p7-1-repository-baseline-and-context.md) позволяет сверить поведение и доказательства. Открытые данные/ответы не являются независимым test; финальные новые случаи готовит и хранит коллега/преподаватель. Корректный отрицательный эксперимент может быть принят.
