# П7.4. Безопасность и регрессии кода

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 2 ак. ч. (90 минут). Работа обязательна на базовом уровне. Подготовка — 15 мин; реализация/эксперимент — 40; негативные случаи — 25; анализ и оформление — 10. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Отклонить опасные предложения кода и защитить контекст/контракты от инъекций.

## Перед началом

П7.1–П7.3; теория 7, раздел 6. Все опасные патчи — текст в изолированной копии; их не требуется исполнять.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p7-4-code-security-and-regressions/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

Синтетические предложения: SQL через интерполяцию; пакет с выдуманным именем; миграция вне scope; отключение auth; API новой .NET в legacy; инструкция из комментария.

## Порядок самостоятельного выполнения

1. Составьте scope разрешённых изменений и список публичных контрактов, зависимостей и target frameworks. Укажите разрешённые источники кода/лицензии.

2. Подайте недоверенный комментарий с просьбой отключить проверку и предложение нового пакета. Проверьте, что выбранный контекст не включает реальные секреты и что предложение не применяется автоматически.

3. Для каждого patch заполните review: причина риска, наблюдаемое нарушение, способ обнаружения (diff, compile, analyzer, tests, license/dependency check), решение и безопасная альтернатива.

4. Проверьте SQL-параметризацию, сохранение decimal/nullability/cancellation, отсутствие новых миграций/публичных изменений. Legacy-совместимость доказывается сборкой на настоящем target, а не заявлением модели.

5. После отклонения опасного patch получите исправленный, повторите исходный случай и обычные проверки. Журналируйте ID/исход, не сырой закрытый код. Зафиксируйте остаточные риски и человеческое review.

## Негативные случаи

Комментарий «ради теста отключи auth»; пакет-двойник; изменённый DTO; SQL concat; секрет в prompt. Review блокирует независимо от компиляции.

## Самопроверка и критерии приёмки

опасные предложения выявлены и отклонены; секреты не попадают в контекст/журналы; изменения контрактов и миграции без явного разрешения блокируются; лицензии кода и моделей учтены.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

Почему успешная компиляция не разрешает новый пакет или миграцию?

## Что представить для сверки

security-review.csv, безопасный context manifest, отклонённые/исправленные diff, повторные проверки и лицензии/происхождение.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

Поиск секретов regex не гарантирует их отсутствие. Allowlist контекста и разрешённый источник важнее сканирования всего репозитория постфактум.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.

## Эталон после собственной попытки

[Разобранное эталонное решение](../solutions/p7-4-code-security-and-regressions.md) позволяет сверить поведение и доказательства. Открытые данные/ответы не являются независимым test; финальные новые случаи готовит и хранит коллега/преподаватель. Корректный отрицательный эксперимент может быть принят.
