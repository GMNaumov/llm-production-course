# П0.1. Карта возможностей и baseline

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 2 ак. ч. (90 минут). Работа обязательна на базовом уровне. Подготовка — 15 мин; реализация/эксперимент — 40; негативные случаи — 25; анализ и оформление — 10. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Выбрать пилоты по измеримому затруднению процесса и составить проверяемый baseline.

## Перед началом

Прочитайте разделы 1–4 теории модуля 0. Нужны таблица/редактор Markdown; Docker нужен только для сверки расчётов.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p0-1-process-map-and-baseline/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

Синтетические времена поиска в `scripts/demo.py::baseline`: 240, 180, 300, 210, 270, 600, 120, 360, 240, 180 секунд; две переделки из десяти. Дополнительно рассмотрите перенос спецификации, чтение заказа и C#-патч.

## Порядок самостоятельного выполнения

1. Создайте `work/p0-1/processes.csv`: процесс, единица работы, вход/выход, исполнитель, источник истины, активное время, время цикла, переделки, стоимость ошибки, данные/права, владелец. Заполните 3–5 строк. Неизвестное обозначайте `не измерено`, а не нулём.

2. Для поиска посчитайте P50/P95 правилом nearest rank, долю переделок и стоимость проверенного результата. Для остальных процессов задайте план: кто, на каких случаях, каким инструментом и когда измерит baseline.

3. Разделите ограничения на блокирующие и сравнимые. Исключите автономную производственную запись; при отсутствии прав/эксперта не заменяйте их высокой оценкой ценности.

4. Выберите 2–3 кандидата. Для каждого запишите гипотезу, метрику ценности, допустимый риск, интеграционную сложность, необходимое время эксперта и условие no-go. Объясните, почему отклонён хотя бы один зрелищный кандидат.

5. Проверьте чувствительность выбора: удвойте время ручной проверки и уменьшите поток вдвое. Опишите, изменился ли выбор. Перенесите нерешённые вопросы в реестр зависимостей.

## Команды для воспроизводимого старта

```powershell
docker compose run --rm lab python scripts/demo.py baseline
```

Команды запускают эталонные компоненты/измерения. Скопируйте результаты из `work/` в каталог своего прогона до повторного запуска. Это инженерная проверка поведения, а не автоматическая сдача задания.

## Негативные случаи

Кандидат обещает экономию без baseline; у документа нет разрешения на использование; запись доступна только в production. Во всех трёх случаях требуется сбор доказательств или no-go, а не выдуманное значение.

## Самопроверка и критерии приёмки

у каждого кандидата есть измеримый baseline или план его получения, источник показателей, риск, критерий ценности и оценка интеграционной сложности; выбор не основан только на зрелищности демо.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

Почему два процесса с одинаковыми 5 минутами активного времени могут иметь разные приоритеты? Покажите разницу стоимости ошибки, потока и готовности данных.

## Что представить для сверки

`processes.csv`, `candidates.md` с 2–3 паспортами, `measurement-plan.md`, протокол неизвестных данных и источников.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

P95 оказался максимумом? Для 10 наблюдений nearest rank даёт позицию ceil(0,95×10)=10. Активное время не равно времени цикла. Экспертная оценка без замера остаётся гипотезой.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.

## Эталон после собственной попытки

[Разобранное эталонное решение](../solutions/p0-1-process-map-and-baseline.md) позволяет сверить поведение и доказательства. Открытые данные/ответы не являются независимым test; финальные новые случаи готовит и хранит коллега/преподаватель. Корректный отрицательный эксперимент может быть принят.
