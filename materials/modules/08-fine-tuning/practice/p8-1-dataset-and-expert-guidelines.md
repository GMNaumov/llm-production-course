# П8.1. Датасет и инструкции экспертам

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 4 ак. ч. (180 минут). Работа обязательна на базовом уровне. Подготовка — 25 мин; реализация/эксперимент — 80; негативные случаи — 45; анализ и оформление — 30. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Подготовить прослеживаемый датасет и инструкции разметки без контаминации и навязанной доли синтетики.

## Перед началом

П3.1, диагностика ошибок П1/П4; теория 8, разделы 1–4. Для автономного маршрута данные полностью синтетические, что явно ограничивает вывод.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p8-1-dataset-and-expert-guidelines/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

`prepare_training.py` создаёт 18 train и 6 dev conversational записей; реальные разрешённые данные добавляются только с правом обучения. Финальный test готовит/хранит другой участник.

## Порядок самостоятельного выполнения

1. Опишите диагностированную целевую ошибку: формат статуса/unknown при достаточном контексте. Проверьте, что она не вызвана retrieval/OCR. Составьте data card: происхождение, права, лицензия, классификация, owner и допустимое использование.

2. Запустите генератор, просмотрите каждую роль и метаданные. Синтетика помечена, expert_review до курса должен быть выполнен реальным человеком; метка required не означает проведённую экспертизу.

3. Напишите инструкцию разметчику: статусы, missing/conflict, injection, допустимые альтернативы, эскалация. Два эксперта независимо размечают общую часть, сохраняют разногласия до согласования.

4. Выполните exact/near dedup и групповой split; шаблоны и перефразировки одной семьи не переходят между частями. Метаданные ожидаемого ответа не сериализуются в user prompt. Test не используется для генерации синтетики/negatives.

5. Обоснуйте долю синтетики через дефицит покрытия и качество; в автономном наборе 100% синтетики допустимы только как учебная механика. Обсудите learning curve/нужное покрытие, заблокируйте test и закрепите hashes.

## Команды для воспроизводимого старта

```powershell
docker compose run --rm lab python scripts/prepare_training.py
```

Команды запускают эталонные компоненты/измерения. Скопируйте результаты из `work/` в каталог своего прогона до повторного запуска. Это инженерная проверка поведения, а не автоматическая сдача задания.

## Негативные случаи

Синтетическая перефразировка test в train; source без права обучения; метка required выдана за expert approved; общий шаблон пересекает split.

## Самопроверка и критерии приёмки

доля синтетики обоснована, а не задана заранее; источники и лицензии указаны; синтетика маркирована и проверена экспертом на выборке; выполнены дедупликация, групповой split и блокировка теста; правила разметки, примеры, эскалация и согласованность на общей выборке задокументированы.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

## Что представить для сверки

data card/manifest, JSONL, dedup/split report, инструкция/согласованность экспертов и реестр тестового хранения.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

18 строк достаточно, чтобы исполнить шаг обучения, но недостаточно доказать перенос. Простая проверка group ID не обнаруживает смысловые дубли: нужен просмотр.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.

## Эталон после собственной попытки

[Разобранное эталонное решение](../solutions/p8-1-dataset-and-expert-guidelines.md) позволяет сверить поведение и доказательства. Открытые данные/ответы не являются независимым test; финальные новые случаи готовит и хранит коллега/преподаватель. Корректный отрицательный эксперимент может быть принят.
