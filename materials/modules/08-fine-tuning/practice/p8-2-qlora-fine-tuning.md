# П8.2. QLoRA-дообучение

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 5 ак. ч. (225 минут). Работа обязательна на базовом уровне. Подготовка — 35 мин; реализация/эксперимент — 100; негативные случаи — 55; анализ и оформление — 35. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Выполнить настоящий QLoRA-эксперимент и загрузить адаптер в тот же путь serving.

## Перед началом

П8.1, П2.1–П2.3; теория 8, разделы 5–6 и 8. Организатор заранее проверяет CUDA/библиотеки/модель на 12 ГБ; сохранён on-prem резерв.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p8-2-qlora-fine-tuning/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

`train_qlora.py`, локальный chat-small snapshot, train/dev JSONL. Маленькая 0,5B — базовый воспроизводимый учебный путь; 7–8B только после отдельного memory preflight.

## Порядок самостоятельного выполнения

1. Остановите inference/VLM перед обучением. Зафиксируйте baseline через API, model revision/checksums, tokenizer/template, длины данных и предел контекста. Убедитесь, что ответы не отрезаются и assistant-only маска корректна.

2. На небольшой конфигурации выполните 2–8 smoke steps, включая самый длинный допустимый пример/backward/optimizer step. Снимите peak allocated/reserved и nvidia-smi. Успешный load не считается проверкой обучения.

3. Запустите согласованный эксперимент с фиксированными rank/modules, microbatch, accumulation, LR, steps, seed. Эталон использует NF4, double quant, FP16 compute, r=8 q_proj/v_proj; это конфигурация механики, не обещанный optimum.

4. Сохраните адаптер, tokenizer/template, run.json и зависимости. Выбор checkpoint/параметров делайте только по dev; test остаётся закрытым. При OOM уменьшите модель/длину только с фиксацией изменения задачи или используйте резерв.

5. Перезапустите serving с QUANTIZE=1 и ADAPTER_PATH=/kit/work/adapter. Выполните те же запросы через API, затем финальную оценку П8.4. Не выдавайте снижение training loss за улучшение целевого качества.

## Команды для воспроизводимого старта

```powershell
docker compose stop inference
docker run --rm --gpus all --network none --mount "type=bind,source=${PWD},target=/kit" --mount "type=bind,source=${PWD}/models,target=/models,readonly" course-gpu:2026-11 python scripts/train_qlora.py --steps 40
$env:QUANTIZE='1'
$env:ADAPTER_PATH='/kit/work/adapter'
docker compose --profile gpu up -d --force-recreate inference
```

Команды запускают эталонные компоненты/измерения. Скопируйте результаты из `work/` в каталог своего прогона до повторного запуска. Это инженерная проверка поведения, а не автоматическая сдача задания.

## Негативные случаи

Truncation отрезает assistant; mask включает только prompt; trainable parameters=0; OOM на backward; serving без адаптера; другой template.

## Самопроверка и критерии приёмки

сохранены базовая модель/версия, токенизатор, chat template, данные, конфигурация, гиперпараметры, зависимости и применимые seed; адаптер загружается в согласованный serving; измерены VRAM и время; при несовместимости 7–8B используется заранее проверенная меньшая конфигурация или on-prem резерв без потери методики эксперимента.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

## Что представить для сверки

adapter/tokenizer/run.json, baseline и serving результаты, hashes/config/версии/seed, peak VRAM/время и анализ ограничений.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

Нельзя обучать GGUF как bitsandbytes NF4. На другой GPU, особенно с иной архитектурой, пересоберите совместимый CUDA стек; не обещайте вместимость 7–8B по результату 0,5B.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.

## Эталон после собственной попытки

[Разобранное эталонное решение](../solutions/p8-2-qlora-fine-tuning.md) позволяет сверить поведение и доказательства. Открытые данные/ответы не являются независимым test; финальные новые случаи готовит и хранит коллега/преподаватель. Корректный отрицательный эксперимент может быть принят.
