# П4.4. Жизненный цикл корпуса

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 2 ак. ч. (90 минут). Работа обязательна на базовом уровне. Подготовка — 15 мин; реализация/эксперимент — 40; негативные случаи — 25; анализ и оформление — 10. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Обновить и восстановить индекс без возвращения удалённых документов и отозванных прав.

## Перед началом

П4.1–П4.3; теория 4, раздел 6. Состояние учебное; запрещено удалять чужие volumes.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p4-4-corpus-lifecycle/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

`scripts/lifecycle.py`, исходный corpus, current rights ledger; для своего индекса — копия и manifest embedding/chunker.

## Порядок самостоятельного выполнения

1. Создайте snapshot корпуса/индекса с checksum и версиями модели/chunker. Опишите, как переключается цельный набор текстов и векторов без смешения редакций.

2. В копии добавьте release r3 с новым синтетическим правилом и снимите active с r2. Переиндексируйте затронутые фрагменты; ответ обязан ссылаться на r3.

3. Удалите release и отзовите shortage для A. Проверьте поиск, цитату по прямому ID, cache и историю, если они существуют. Нет кэша — явно запишите это, не заявляйте проверку отсутствующего компонента.

4. Восстановите старый backup, затем наложите актуальные tombstones/отзывы до допуска запросов. Сверьте, что удалённые/отозванные источники не вернулись. Для embeddings смена пространства требует переиндексации.

5. Составьте протокол update/delete/revoke/restore с состоянием до/после и временем. Объясните retention резервов и ответственного за повторную проверку прав.

## Команды для воспроизводимого старта

```powershell
docker compose run --rm lab python scripts/lifecycle.py
```

Команды запускают эталонные компоненты/измерения. Скопируйте результаты из `work/` в каталог своего прогона до повторного запуска. Это инженерная проверка поведения, а не автоматическая сдача задания.

## Негативные случаи

Старый backup содержит разрешение, которого больше нет; кэш возвращает прежний ответ; ссылка открывает удалённый текст; вектора старой модели смешаны с новой.

## Самопроверка и критерии приёмки

тесты подтверждают прекращение использования удалённого документа и отозванных прав, идентификацию версии источника в ответе и восстановление индекса из согласованной копии.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

## Что представить для сверки

snapshots/manifest, журнал событий и текущих прав, код обновления, матрица проверок lifecycle и runbook restore.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

Удаление из index без удаления text store/кэша недостаточно. Restore поднимает данные, но актуальная политика/журнал отзывов должны переживать откат отдельно.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.

## Эталон после собственной попытки

[Разобранное эталонное решение](../solutions/p4-4-corpus-lifecycle.md) позволяет сверить поведение и доказательства. Открытые данные/ответы не являются независимым test; финальные новые случаи готовит и хранит коллега/преподаватель. Корректный отрицательный эксперимент может быть принят.
