# Эталон П1.3. Выбор подхода

[Задание](../practice/p1-3-approach-selection.md) · [Теория](../self-study.md) · [Правила сверки](../../../practice-kit/README.md)

Эталон показывает один корректный вариант и границы вывода. Сначала выполните собственную попытку; затем сравните поведение, методику и причины расхождений. Код и таблицы не оценивают работу участника автоматически.

## Разбор решения

Поиск актуального регламента: сначала lexical + фильтры редакции, затем RAG при доказанной пользе сводки. Перенос спецификации: PDF/OCR + schema/provenance + HITL; VLM только для диагностированных сложных областей. Дефицит: параметризованный semantic layer и обычная формула, LLM может выбрать разрешённую операцию.

Fine-tuning рассматривается для устойчивого нарушения формата/поведения на качественных данных; он не заменяет актуальные статусы и ACL. Во всех трёх строках остаётся измеримый вариант без LLM.

## Как сравнить собственный результат

1. Сопоставьте артефакты с каждым критерием [программы](../../../../curriculum.md) и задания. Укажите доказательство.
2. Разберите хотя бы одно расхождение: методика, набор/версия, ошибка кода, неопределённость или ожидание. Не подгоняйте финальный test под эталон.
3. Подтвердите негативные случаи: «Все знания в веса», «RAG исправит нечитаемый допуск», «LLM сама посчитает SQL». Найдите границу применимости каждого утверждения.
4. Зафиксируйте ограничения: Обещания эффекта без эксперимента помечайте гипотезами. Наличие fine-tuning в программе не делает его обязательным для выбранного capstone.
5. Передайте отчёт на ручное review. При одиночном прохождении независимая проверка остаётся ожидающей коллегу/преподавателя; собственная сверка её не заменяет.

## Пример артефакта для сверки

| Задача | Без LLM | Prompting | RAG | Fine-tuning | Первое решение |
|---|---|---|---|---|---|
| Действующий регламент | Поиск/версия/ACL | Нет live-источника | Сводка с цитатой | Не решает права/обновления | Поиск, затем измерить RAG |
| Поля спецификации | PDF/OCR/schema | Извлечение прочитанного | Только при внешних знаниях | После диагностики поведения | OCR/JSON/HITL |
| Дефицит | SQL/формула | Выбор узкой операции | Не источник live-остатков | Не хранилище статуса | Semantic layer |

Пересмотр происходит по измеренным ошибкам, стоимости review, изменившимся данным/риску, а не по популярности технологии.

## Контрольный вопрос

Какое наблюдение заставит заменить RAG улучшением OCR, а не новым промптом?

Итог — аргументированное решение на измеренных данных. Latency/VRAM/стоимость зависят от среды и состава случаев; открытые синтетические результаты не обещают качество предприятия.
