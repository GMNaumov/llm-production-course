# Эталон П5.5. Отказы и неблагоприятные документы

[Задание](../practice/p5-5-failures-and-adverse-documents.md) · [Теория](../self-study.md) · [Правила сверки](../../../practice-kit/README.md)

Эталон показывает один корректный вариант и границы вывода. Сначала выполните собственную попытку; затем сравните поведение, методику и причины расхождений. Код и таблицы не оценивают работу участника автоматически.

## Разбор решения

Потеря поля при crop должна снизить completeness/вызвать unreadable, а не восстановить число из другой страницы или ожидаемой нумерации. Повтор обработки с тем же ключом pipeline заменяет/возвращает один логический результат.

Идемпотентность этапов означает ключ и устойчивое состояние обработки; словарь памяти недостаточен после рестарта. Ошибки зависимости сохраняют отдельную категорию, поскольку retry может быть допустим, а нечитаемая область требует человека.

## Как сравнить собственный результат

1. Сопоставьте артефакты с каждым критерием [программы](../../../../curriculum.md) и задания. Укажите доказательство.
2. Разберите хотя бы одно расхождение: методика, набор/версия, ошибка кода, неопределённость или ожидание. Не подгоняйте финальный test под эталон.
3. Подтвердите негативные случаи: Обрезано количество; росчерк поверх допуска; 90° поворот; повреждённый PDF; процесс OCR убит; размер выше лимита. Ни один случай не даёт выдуманного критичного значения.
4. Зафиксируйте ограничения: Росчерк генератора не эквивалентен настоящей рукописи; для промышленного покрытия нужен разрешённый набор реальных пометок. Не обещайте, что один threshold качества скана работает на всех шаблонах.
5. Передайте отчёт на ручное review. При одиночном прохождении независимая проверка остаётся ожидающей коллегу/преподавателя; собственная сверка её не заменяет.

## Пример артефакта для сверки

| Отказ | Статус/действие | Что запрещено |
|---|---|---|
| Повреждённый PDF | parse_error | Продолжать как с полноценным текстом |
| OCR timeout | dependency_error, ограниченный retry | Угадать количество |
| Допуск обрезан | unreadable + человек | Восстановить по похожей детали |
| Шум/печать | Отдельный срез/source review | Скрыть ошибки средним CER |
| Повтор файла/версии pipeline | Один логический результат | Дублировать позиции |

Ключ exact-file повторов: checksum оригинала + pipeline version. Повторный скан с другим hash требует дополнительного поиска близких дублей.

## Контрольный вопрос

Почему нельзя считать отсутствие исключения достаточным доказательством безопасного отказа?

Итог — аргументированное решение на измеренных данных. Latency/VRAM/стоимость зависят от среды и состава случаев; открытые синтетические результаты не обещают качество предприятия.
