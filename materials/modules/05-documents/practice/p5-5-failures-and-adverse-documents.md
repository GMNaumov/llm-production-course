# П5.5. Отказы и неблагоприятные документы

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 2 ак. ч. (90 минут). Работа обязательна на базовом уровне. Подготовка — 15 мин; реализация/эксперимент — 40; негативные случаи — 25; анализ и оформление — 10. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Обеспечить контролируемые отказы обработки документов и безопасное повторение этапов.

## Перед началом

П5.1–П5.4; теория 5, разделы 1, 6–7. Работайте с копиями синтетических файлов.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p5-5-failures-and-adverse-documents/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

Варианты rotated, blur, cropped, stamp-notes и broken.pdf из генератора; дополнительно зашифрованный/пустой PDF и смоделированный отказ OCR/VLM.

## Порядок самостоятельного выполнения

1. Создайте матрицу дефект→ожидаемый результат: восстановимое качество, review, отказ парсера/зависимости. До теста определите лимиты размера файла, страниц, пикселей, времени, памяти и попыток.

2. Запустите все варианты и сохраните штатные/ошибочные исходы в одном реестре. Для PDF-рендера используйте отдельный контейнер с лимитами и timeout; расширение .pdf не гарантирует корректный вход.

3. Прервите OCR/VLM на этапе. Проверьте, что downstream получает состояние dependency_error/unreadable, а не пустой текст, который LLM заполняет догадкой.

4. Задайте идентификатор обработки как checksum оригинала + версия pipeline. Повторите документ после сбоя и убедитесь, что результат не размножает позиции/записи в очереди. Отдельно опишите ограничение повторных сканов, не совпадающих по hash.

5. Проверьте отсутствие сырого содержимого/traceback в пользовательском статусе и общих логах. Составьте карту применимости, план исправления и повторите исходный дефект после изменения.

## Команды для воспроизводимого старта

```powershell
docker compose run --rm lab python scripts/documents.py ocr
# Смотрите work/ocr-results.json: не исключайте failed/unreadable из отчёта.
```

Команды запускают эталонные компоненты/измерения. Скопируйте результаты из `work/` в каталог своего прогона до повторного запуска. Это инженерная проверка поведения, а не автоматическая сдача задания.

## Негативные случаи

Обрезано количество; росчерк поверх допуска; 90° поворот; повреждённый PDF; процесс OCR убит; размер выше лимита. Ни один случай не даёт выдуманного критичного значения.

## Самопроверка и критерии приёмки

ни один отказ зависимости не приводит к выдуманному критичному значению; ошибки классифицированы; повторная обработка не создаёт неконтролируемых дублей; указаны ограничения применимости пайплайна.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

Почему нельзя считать отсутствие исключения достаточным доказательством безопасного отказа?

## Что представить для сверки

матрица негативных случаев, реестр исходов, limits/retry/idempotency, след повторного запуска и ограничения.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

Росчерк генератора не эквивалентен настоящей рукописи; для промышленного покрытия нужен разрешённый набор реальных пометок. Не обещайте, что один threshold качества скана работает на всех шаблонах.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.

## Эталон после собственной попытки

[Разобранное эталонное решение](../solutions/p5-5-failures-and-adverse-documents.md) позволяет сверить поведение и доказательства. Открытые данные/ответы не являются независимым test; финальные новые случаи готовит и хранит коллега/преподаватель. Корректный отрицательный эксперимент может быть принят.
