# П5.1. OCR-пайплайн и раздельная оценка

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 3 ак. ч. (135 минут). Работа обязательна на базовом уровне. Подготовка — 20 мин; реализация/эксперимент — 60; негативные случаи — 35; анализ и оформление — 20. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Измерить отдельно OCR-текст, порядок блоков и строки таблицы на смешанных документах.

## Перед началом

Теория 5, разделы 1–3 и 7; П3.1. CPU-образ содержит Tesseract rus+eng, Poppler, pypdf и шрифт с кириллицей.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p5-1-ocr-pipeline-and-evaluation/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

Генератор `documents.py`: 4 семейства × 2 страницы × 5 вариантов = 40 PNG, текстовые двухстраничные PDF и PDF со сканом. Эталоны открытые; для независимого test нужны новые документы/шаблоны.

## Порядок самостоятельного выполнения

1. Сгенерируйте входы, просмотрите оригиналы и manifest. Разделите по семье документа, а не по страницам. Зафиксируйте пробельную/Unicode-нормализацию, сохранение знаков ± и единиц.

2. Сравните готовый текст pypdf у text PDF и scan PDF. Пустое извлечение из скана — корректное ограничение baseline; оно не заменяется выдуманным текстом.

3. Запустите настоящий Tesseract с TSV-координатами/confidence. Для двух страниц попробуйте поворот/масштабирование и сравните с исходным вариантом на dev, сохранив оригинал.

4. Посчитайте CER/WER по страницам и срезам. Отдельно вручную разметьте и измерьте порядок блоков, число/порядок колонок, соответствие позиция–обозначение–количество–единица, повтор заголовка/связь двух страниц. OCR-script считает текстовые метрики; структуру/таблицы нужно дополнить.

5. Замерьте P95 и стоимость страницы с учётом обработки отказов и ручной проверки. Составьте вывод по кириллице, печатям, мелкому тексту, поворотам и разным шаблонам; не обобщайте синтетический результат на реальную рукопись.

## Команды для воспроизводимого старта

```powershell
docker compose run --rm lab python scripts/documents.py generate
docker compose run --rm lab python scripts/documents.py ocr
```

Команды запускают эталонные компоненты/измерения. Скопируйте результаты из `work/` в каталог своего прогона до повторного запуска. Это инженерная проверка поведения, а не автоматическая сдача задания.

## Негативные случаи

Повернутая/обрезанная страница, печать поверх количества, продолжение таблицы, broken.pdf. Пустой результат остаётся отказом/пропуском.

## Самопроверка и критерии приёмки

отдельно измерены качество текста, структуры и таблиц на эталонном наборе; результаты сравнены с базовым извлечением; есть разбор по шаблонам, качеству сканов, кириллице и многостраничным таблицам, а также P95 latency и стоимость страницы.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

## Что представить для сверки

manifest/split, OCR TSV/текст, CER/WER и отдельные таблицы структуры/ячеек, P95/стоимость и примеры ошибок.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

Tesseract TSV не является layout/table parser. Наличие разделителей | не доказывает правильную таблицу. CER может быть больше 1; не обрезайте вставки до 100%.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.
