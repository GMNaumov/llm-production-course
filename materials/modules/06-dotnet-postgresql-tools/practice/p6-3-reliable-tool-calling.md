# П6.3. Надёжный tool-calling

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 4 ак. ч. (180 минут). Работа обязательна на базовом уровне. Подготовка — 25 мин; реализация/эксперимент — 80; негативные случаи — 45; анализ и оформление — 30. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Реализовать ограниченный диспетчер инструментов с независимой авторизацией и предсказуемым частичным отказом.

## Перед началом

П6.1–П6.2; теория 6, разделы 5–6. Нет производственных write-инструментов.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p6-3-reliable-tool-calling/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

`scripts/tool_dispatch.py`, `tools.py`; пять синтетических вызовов, включая запрещённый write и неверный объект.

## Порядок самостоятельного выполнения

1. Определите строгие schemas имени и аргументов: дополнительные поля запрещены, диапазоны/ID проверяются. Actor/scope не входят в модельные аргументы: их передаёт доверенный контекст.

2. Получите предложение tool-call от локальной модели в JSON либо воспроизведите сохранённое модельное сообщение. Отделите proposal от исполнения. Невалидный JSON, неизвестное имя и подставленная роль отклоняются диспетчером.

3. Реализуйте независимую авторизацию внутри каждого инструмента. Ограничьте число параллельных независимых reads и общий бюджет шагов/времени. Зависимые шаги ждут предыдущий результат.

4. Проверьте частичные исходы через tool_dispatch: один успешный read, forbidden, 503 и timeout, неверная schema. Retry чтения ограничен, вредоносное примечание tool output не вызывает новое действие.

5. Для эффектов исполните отдельный preview/confirm эталон и повтор после нового соединения. Расширьте испытание конкурентным подтверждением и повтором с другим payload; покажите один эффект и controlled conflict. Сохраните трассу ID/статусов и состояние.

## Команды для воспроизводимого старта

```powershell
docker compose run --rm lab python scripts/tool_dispatch.py
docker compose run --rm lab python scripts/demo.py effects
```

Команды запускают эталонные компоненты/измерения. Скопируйте результаты из `work/` в каталог своего прогона до повторного запуска. Это инженерная проверка поведения, а не автоматическая сдача задания.

## Негативные случаи

Actor=admin в JSON, лишний аргумент, unknown tool, tool output просит write, повтор после timeout. Модель не создаёт новые полномочия.

## Самопроверка и критерии приёмки

инструмент сам проверяет права и аргументы; вредоносный tool output не воспринимается как инструкция; тесты подтверждают контроль параллельности, отсутствие повторного эффекта при replay и корректное завершение при частичном отказе.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

## Что представить для сверки

schemas/dispatcher, бюджеты, результаты parallel/partial failure, протокол идемпотентности и аудит без содержимого.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

asyncio.Semaphore ограничивает только один процесс. Для нескольких replicas нужен общий лимит/пул. In-memory cache не доказывает идемпотентность после перезапуска.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.

## Эталон после собственной попытки

[Разобранное эталонное решение](../solutions/p6-3-reliable-tool-calling.md) позволяет сверить поведение и доказательства. Открытые данные/ответы не являются независимым test; финальные новые случаи готовит и хранит коллега/преподаватель. Корректный отрицательный эксперимент может быть принят.
