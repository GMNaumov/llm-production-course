# Модуль 6. Интеграция с .NET API, PostgreSQL и tool-calling

[Все материалы](../../README.md) · [Программа](../../../curriculum.md)

[Предыдущий модуль](../05-documents/README.md) · [Следующий модуль](../07-dotnet-code-generation/README.md)

От предложения модели к ограниченной серверной операции.

**Объём:** 20 ак. ч.: 4 self-study и 16 контактной практики со встроенной теорией. Отдельные часы лекций не добавляются.

## Результаты теоретической подготовки

После изучения модуля вы сможете:

- Различать аутентификацию и авторизацию.
- Читать контракт API и объяснять назначение семантического слоя.
- Объяснять проверку SQL через AST, идемпотентность и порядок подтверждения действий.

## Как изучать модуль

Основной [конспект теории](self-study.md) содержит маршрут самостоятельного изучения, объяснения, разобранные примеры кода, вопросы с пояснениями и открытые источники. Для коротких вводных блоков и обсуждения ошибок на контактном занятии используется тот же конспект. Код в Markdown демонстрирует отдельный принцип; условия запуска и ограничения указаны рядом.

Вопрос для вводного разбора: **Какие компоненты независимо от модели проверяют права и предотвращают повторный эффект операции?**

## Связь теории с практикой

П6.1 — клиент, секреты и ошибки HTTP; П6.2 — семантика SQL и ограничения доступа; П6.3 — схемы, права, параллелизм и защита от повторного выполнения; П6.4 — состояния рабочего процесса, предпросмотр и HITL.

Критерии приёмки определены в [программе](../../../curriculum.md). В практических заданиях указаны последовательность самостоятельной работы, исходные данные, негативные сценарии и перечень сдаваемых материалов. Начните с [инструкции учебного комплекта](../../practice-kit/README.md). Результат проверяет и принимает человек; автоматического оценивания работ нет.
