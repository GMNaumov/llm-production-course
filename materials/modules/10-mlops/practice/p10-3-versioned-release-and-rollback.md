# П10.3. Версионированный выпуск и откат

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 2 ак. ч. (90 минут). Работа обязательна на базовом уровне. Подготовка — 15 мин; реализация/эксперимент — 40; негативные случаи — 25; анализ и оформление — 10. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Выпустить связанный офлайн-комплект и проверить rollback/restore другой командой.

## Перед началом

П2.3, П4.4, П9.1, П10.1–П10.2; теория 10, разделы 5–6.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p10-3-versioned-release-and-rollback/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

`release.py`, Compose/images, model manifests, prompt/config/schema, corpus/index, adapter при использовании и current rights ledger.

## Порядок самостоятельного выполнения

1. Составьте manifest всех влияющих артефактов: commit/code, image IDs/digests, model/tokenizer/template/adapter, prompt, data/index/encoder/chunker, tools/policy/config, evaluation report. Скрипт даёт candidate manifest, отсутствующие поля дополняются вручную.

2. Зафиксируйте ручное решение gate/review до выпуска. Сформируйте offline bundle с образами, моделями и исходниками без секретов; проверьте полноту licenses/checksums. Volumes не входят в docker save.

3. Другой участник запускает комплект на чистом context/ПК без pull/build/внешней сети. Записывает фактические действия и результат regression. Личный cache автора не используется.

4. Создайте r2 с контролируемым изменением prompt/config, переключите и затем откатите весь совместимый комплект r1. Убедитесь, что откат не возвращает отозванные права и не повторяет выполненные эффекты.

5. Восстановите индекс/config из backup с актуальными tombstones/rights. Измерьте время и потерю состояния относительно согласованных учебных RTO/RPO, повторите ACL/цитаты/обычные запросы. Опишите владельцев и неизвестные production зависимости.

## Команды для воспроизводимого старта

```powershell
docker compose run --rm lab python scripts/release.py --id training-r1
docker compose run --rm lab python scripts/lifecycle.py
# Экспорт/импорт образов и bundle — по разделу «Офлайн» README комплекта.
```

Команды запускают эталонные компоненты/измерения. Скопируйте результаты из `work/` в каталог своего прогона до повторного запуска. Это инженерная проверка поведения, а не автоматическая сдача задания.

## Негативные случаи

Откат только image; новый index со старым encoder; backup возвращает B/revoked; повтор эффекта после восстановления; пакет содержит secrets.

## Самопроверка и критерии приёмки

manifest связывает код, модель/адаптер, промпты, данные, индекс и схемы; другой участник выполняет офлайн-развёртывание, откат и восстановление индекса/конфигурации по README; регрессионные проверки запускаются до выпуска.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

Какие состояния нельзя безопасно откатить одновременно с кодом и почему?

## Что представить для сверки

полный manifest/bundle/checksums, протокол независимого запуска, rollout/rollback/restore trace, актуальные права и runbook.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

candidate manifest со строкой «attach report» не является готовым выпуском. Пустой adapter должен быть явно null с обоснованием, неизвестный digest — незавершённое поле.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.

## Эталон после собственной попытки

[Разобранное эталонное решение](../solutions/p10-3-versioned-release-and-rollback.md) позволяет сверить поведение и доказательства. Открытые данные/ответы не являются независимым test; финальные новые случаи готовит и хранит коллега/преподаватель. Корректный отрицательный эксперимент может быть принят.
