# П10.1. API-шлюз и безопасная наблюдаемость

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 3 ак. ч. (135 минут). Работа обязательна на базовом уровне. Подготовка — 20 мин; реализация/эксперимент — 60; негативные случаи — 35; анализ и оформление — 20. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Развернуть API-границу с политиками, бюджетами и минимальным аудитом.

## Перед началом

П6.3, П9.1; теория 10, разделы 1–2. Учебный gateway один процесс с фиксированной ролью A; enterprise IdP пока не определён.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p10-1-api-gateway-and-safe-observability/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

`gateway.py`, Compose, secrets-init, search/rag routes; случайный токен доступен только gateway/lab через отдельный Docker volume.

## Порядок самостоятельного выполнения

1. Опишите доверенную идентичность и разрешённые маршруты. Клиент не выбирает plant, model path, system prompt или адрес инструментов. Запустите gateway и проверьте запрос без токена/с неверным токеном.

2. Реализуйте/прочитайте rate limit, quota и concurrency. В эталоне quota по запросам на жизнь одного процесса; для настоящего сервиса определите серверный токен/страничный бюджет, период и общий устойчивый storage.

3. Свяжите запрос с release, model/prompt/config/policy версией. Audit содержит только allowlist метаданных и server-generated ID. Принудительно вызовите 401/422/429/dependency_error и проверьте, что exception не экспортирует body/secret.

4. Проверьте маршрутизацию search/rag и readiness зависимости. При отказе модели допускается явно маркированный degraded_search с теми же ACL; автоматический fallback в облако исключён.

5. Просмотрите журналы/traces/UI history по правилам доступа/retention. Для предприятия согласуйте IdP, quota persistence, secret provider и audit owner. Отдельно перечислите ограничения учебного варианта.

## Команды для воспроизводимого старта

```powershell
docker compose run --rm secrets-init
docker compose up -d gateway
docker compose run --rm lab python scripts/load.py --route search --clients 1 --requests 10
```

Команды запускают эталонные компоненты/измерения. Скопируйте результаты из `work/` в каталог своего прогона до повторного запуска. Это инженерная проверка поведения, а не автоматическая сдача задания.

## Негативные случаи

Actor/plant в payload, клиентский model path, unknown route, пустой/слишком длинный вопрос, rate overflow, missing secret. Отказы без раскрытия данных.

## Самопроверка и критерии приёмки

проверены авторизация, маршрутизация, квоты, rate limits и аудит; версии промпта/модели/конфигурации связаны с запросом; в журналах отсутствуют секреты и неразрешённые содержимые документы, код, токены и SQL-результаты.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

## Что представить для сверки

gateway/config, матрица auth/routes/budgets, audit samples без токенов/текста, политики retention и список production gaps.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

Один токен учебной роли не доказывает enterprise identity. In-memory quota обнуляется после рестарта и не подходит для нескольких replicas; это ограничение надо исправить перед промышленным пилотом.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.
