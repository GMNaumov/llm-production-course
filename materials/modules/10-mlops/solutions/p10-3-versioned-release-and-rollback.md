# Эталон П10.3. Версионированный выпуск и откат

[Задание](../practice/p10-3-versioned-release-and-rollback.md) · [Теория](../self-study.md) · [Правила сверки](../../../practice-kit/README.md)

Эталон показывает один корректный вариант и границы вывода. Сначала выполните собственную попытку; затем сравните поведение, методику и причины расхождений. Код и таблицы не оценивают работу участника автоматически.

## Разбор решения

Эталон выпуска связывает содержимое файлов SHA-256, model-source manifests и image IDs, а отдельно прикладывает одобренные evaluation/rights/adapter. Release r1/r2 — целые комплекты, а не разные теги одного контейнера.

Восстановление применяет текущую политику поверх старых данных. Секреты выдаются заново согласованным provider; их не копируют в bundle и не откатывают вместе с кодом. RTO измеряется фактическим восстановлением, не обещанием.

## Как сравнить собственный результат

1. Сопоставьте артефакты с каждым критерием [программы](../../../../curriculum.md) и задания. Укажите доказательство.
2. Разберите хотя бы одно расхождение: методика, набор/версия, ошибка кода, неопределённость или ожидание. Не подгоняйте финальный test под эталон.
3. Подтвердите негативные случаи: Откат только image; новый index со старым encoder; backup возвращает B/revoked; повтор эффекта после восстановления; пакет содержит secrets.
4. Зафиксируйте ограничения: candidate manifest со строкой «attach report» не является готовым выпуском. Пустой adapter должен быть явно null с обоснованием, неизвестный digest — незавершённое поле.
5. Передайте отчёт на ручное review. При одиночном прохождении независимая проверка остаётся ожидающей коллегу/преподавателя; собственная сверка её не заменяет.

## Контрольный вопрос

Какие состояния нельзя безопасно откатить одновременно с кодом и почему?

Итог — аргументированное решение на измеренных данных. Latency/VRAM/стоимость зависят от среды и состава случаев; открытые синтетические результаты не обещают качество предприятия.
