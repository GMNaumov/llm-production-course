# Эталон П10.1. API-шлюз и безопасная наблюдаемость

[Задание](../practice/p10-1-api-gateway-and-safe-observability.md) · [Теория](../self-study.md) · [Правила сверки](../../../practice-kit/README.md)

Эталон показывает один корректный вариант и границы вывода. Сначала выполните собственную попытку; затем сравните поведение, методику и причины расхождений. Код и таблицы не оценивают работу участника автоматически.

## Разбор решения

Аудит охватывает неожиданные исключения обработчика: безопасный 503 получает серверный request ID и запись без текста исключения. Слот concurrency освобождается в `finally`. При пустом `choices` или нестроковом `content` шлюз возвращает `degraded_search` с разрешёнными источниками. HTTP 200 такой деградации не считается успешной генерацией. Ошибки JSONL-хранилища, несколько процессов и устойчивые квоты требуют отдельной эксплуатационной реализации.

Эталон публикует только loopback gateway, внутренние API не опубликованы. Ask принимает question и route=search/rag; schema forbids extras. 401 означает отсутствие identity, 422 — неверный контракт, 429 — бюджет/занятость.

Audit не содержит Authorization, URL/query/body, raw prompt, source text или SQL-результат. ID создаётся сервером. Генерация возвращается draft_for_review, поскольку смысл ответа не доказывается HTTP 200. Без модели — degraded_search, а не выдуманный ответ.

## Как сравнить собственный результат

1. Сопоставьте артефакты с каждым критерием [программы](../../../../curriculum.md) и задания. Укажите доказательство.
2. Разберите хотя бы одно расхождение: методика, набор/версия, ошибка кода, неопределённость или ожидание. Не подгоняйте финальный test под эталон.
3. Подтвердите негативные случаи: Actor/plant в payload, клиентский model path, unknown route, пустой/слишком длинный вопрос, rate overflow, missing secret. Отказы без раскрытия данных.
4. Зафиксируйте ограничения: Один токен учебной роли не доказывает enterprise identity. In-memory quota обнуляется после рестарта и не подходит для нескольких replicas; это ограничение надо исправить перед промышленным пилотом.
5. Передайте отчёт на ручное review. При одиночном прохождении независимая проверка остаётся ожидающей коллегу/преподавателя; собственная сверка её не заменяет.

## Контрольный вопрос

Чем отличаются rate limit, quota и concurrency limit в вашем сервисе?

Итог — аргументированное решение на измеренных данных. Latency/VRAM/стоимость зависят от среды и состава случаев; открытые синтетические результаты не обещают качество предприятия.
