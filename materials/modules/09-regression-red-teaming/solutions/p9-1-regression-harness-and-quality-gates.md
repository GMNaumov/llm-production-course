# Эталон П9.1. Регрессионный контур и quality gates

[Задание](../practice/p9-1-regression-harness-and-quality-gates.md) · [Теория](../self-study.md) · [Правила сверки](../../../practice-kit/README.md)

Эталон показывает один корректный вариант и границы вывода. Сначала выполните собственную попытку; затем сравните поведение, методику и причины расхождений. Код и таблицы не оценивают работу участника автоматически.

## Разбор решения

Эталон gate выдаёт pass только при полном конечном наборе измерений и пройденных порогах; critical>0→fail; нет измерения/NaN→insufficient evidence. Условный quality=0,7 при minimum=0,9 даёт fail.

Реальный release report дополнительно проверяет покрытие/объём, права, версии и допустимое ухудшение от baseline. Формально зелёный вычислительный gate не отменяет ручного review и критичных ограничений.

## Как сравнить собственный результат

1. Сопоставьте артефакты с каждым критерием [программы](../../../../curriculum.md) и задания. Укажите доказательство.
2. Разберите хотя бы одно расхождение: методика, набор/версия, ошибка кода, неопределённость или ожидание. Не подгоняйте финальный test под эталон.
3. Подтвердите негативные случаи: Нет p95, quality=NaN, отсутствует ACL-run, хороший средний score при одной утечке, известный regression выдан за независимый test.
4. Зафиксируйте ограничения: Знакомые случаи полезны для регрессий, но не подтверждают перенос. Перенос порогов из demo без связи с риском не выполняет задание.
5. Передайте отчёт на ручное review. При одиночном прохождении независимая проверка остаётся ожидающей коллегу/преподавателя; собственная сверка её не заменяет.

## Контрольный вопрос

Почему insufficient evidence нельзя автоматически трактовать как pass?

Итог — аргументированное решение на измеренных данных. Latency/VRAM/стоимость зависят от среды и состава случаев; открытые синтетические результаты не обещают качество предприятия.
