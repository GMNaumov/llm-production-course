# П2.2. Docker Compose стенд

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 3 ак. ч. (135 минут). Работа обязательна на базовом уровне. Подготовка — 20 мин; реализация/эксперимент — 60; негативные случаи — 35; анализ и оформление — 20. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Собрать управляемый локальный стенд inference + UI + FastAPI с проверяемой конфигурацией.

## Перед началом

П2.1, теория 2, разделы 3–4. Подготовка образов/моделей организатором описана в комплекте; время скачивания не включено в 135 минут работы.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p2-2-docker-compose-sandbox/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

`compose.yaml`, `Dockerfile*`, `scripts/model_server.py`, `scripts/gateway.py`; локальные снимки моделей. UI запускается только после подготовки образа и настройки учётной записи.

## Порядок самостоятельного выполнения

1. Прочитайте Compose до запуска: опубликованы только loopback-порты, БД/API/inference доступны внутри internal-сети, модели ro, результаты в work. Нарисуйте, где хранятся данные UI, секреты и состояние.

2. Проверьте `docker compose config --quiet`, создайте учебные секреты и поднимите GPU-профиль с gateway. Проверьте /live и /ready отдельно; отсутствие модели должно влиять на готовность RAG, но не выдавать фиктивный ответ.

3. Добавьте/запустите профиль ui, создайте локальную учётную запись через localhost:3000 и подключите endpoint. В UI нет инструмента write и корпоративных данных. Запишите политику хранения/удаления истории.

4. Сравните float16 и NF4 одной модели на том же наборе: сначала QUANTIZE=0, сохраните benchmark и ресурсы; затем QUANTIZE=1 и пересоздайте inference. Не меняйте промпт/тест между ними.

5. Зафиксируйте image IDs/digests, pip freeze, checksum снимков, template и лимиты. Проверьте запрос без gateway-токена, превышение контекста и недоступность модели. Опишите ограничения учебной аутентификации и subset API.

## Команды для воспроизводимого старта

```powershell
docker compose config --quiet
docker compose --profile gpu up -d inference gateway
docker compose --profile ui up -d webui
docker compose run --rm lab python scripts/benchmark.py --prompt v2
```

Команды запускают эталонные компоненты/измерения. Скопируйте результаты из `work/` в каталог своего прогона до повторного запуска. Это инженерная проверка поведения, а не автоматическая сдача задания.

## Негативные случаи

Нет файла токена; неверный токен; модель остановлена; больше 2048 суммарных токенов; UI пытается использовать неподдерживаемый streaming/tools. Результаты должны быть контролируемыми.

## Самопроверка и критерии приёмки

версии зависимостей закреплены; есть health checks, ограничения доступа и пример конфигурации без секретов; качество выбранной квантованной модели проверено относительно неквантованного или альтернативного baseline на доступном наборе.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

## Что представить для сверки

Compose, схема потоков, manifest версий, таблица float16/NF4, результаты health/auth/timeout и инструкция UI.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

У учебного сервера нет streaming, tool API и constrained JSON. В UI отключите streaming либо используйте benchmark для измерений. Запуск контейнера running не равен readiness. Не публикуйте inference в сеть ради исправления UI.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.
