# П2.3. Воспроизводимость и офлайн-запуск

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 1 ак. ч. (45 минут). Работа обязательна на базовом уровне. Подготовка — 5 мин; реализация/эксперимент — 20; негативные случаи — 10; анализ и оформление — 10. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Воспроизвести подготовленный стенд без интернета и скрытых кэшей.

## Перед началом

П2.2, теория 2, раздел 5. Организатор готовит отдельный Docker context/ПК, локальные образы, снимки и зависимости; не удаляйте чужие volumes ради имитации чистой среды.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p2-3-reproducibility-and-offline/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

Комплект, image archives, модели с `course-source.json`, manifest и инструкция раздела «Офлайн» в README комплекта.

## Порядок самостоятельного выполнения

1. Передайте коллеге исходники, конфигурацию, образы, model snapshots и контрольные суммы без секретов. Секреты он создаёт заново локально. Укажите объём комплекта и разрешённый способ передачи.

2. На другом ПК/context выполните docker load, сверку checksums и запуск с `--pull never --no-build`. Отсутствие артефакта фиксируется как пробел комплекта, а не компенсируется интернетом.

3. При запрещённой телеметрии проверьте отсутствие внешнего egress: internal Docker network плюс наблюдение сетевых событий утверждённым средством предприятия. Переменные OFFLINE сами по себе не доказательство.

4. Выполните benchmark, перезапуск и повторное чтение состояния. Зафиксируйте все ручные действия коллеги и уточните README; результаты сравнивайте по свойствам, не по побитовой строке генерации.

## Команды для воспроизводимого старта

```powershell
docker compose --profile gpu up -d --pull never --no-build inference gateway
docker compose run --rm --pull never lab python scripts/benchmark.py --prompt v2
```

Команды запускают эталонные компоненты/измерения. Скопируйте результаты из `work/` в каталог своего прогона до повторного запуска. Это инженерная проверка поведения, а не автоматическая сдача задания.

## Негативные случаи

Отсутствует tokenizer/config; снимок содержит ссылку на личный cache; digest образа другой; на чистой машине нет UI-образа. До доукомплектования соответствующая часть не воспроизводится.

## Самопроверка и критерии приёмки

запуск выполнен без скрытых ручных действий; тяжёлые артефакты доступны из согласованного локального источника; проверены повторный запуск и отсутствие внешней телеметрии, если она запрещена политикой.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

## Что представить для сверки

протокол запуска коллегой, manifest/checksums, перечень сетевых наблюдений, исправленный README и список ограничений.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

В internal-сети контейнеры общаются друг с другом, но загрузка моделей в ней невозможна. Скачивания выполняют заранее в отдельном подготовительном контейнере. docker save не включает модели/volumes.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.

## Эталон после собственной попытки

[Разобранное эталонное решение](../solutions/p2-3-reproducibility-and-offline.md) позволяет сверить поведение и доказательства. Открытые данные/ответы не являются независимым test; финальные новые случаи готовит и хранит коллега/преподаватель. Корректный отрицательный эксперимент может быть принят.
