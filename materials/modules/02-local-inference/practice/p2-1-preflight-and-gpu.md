# П2.1. Preflight и GPU-проброс

[Теория](../self-study.md) · [Обзор](../README.md) · [Программа](../../../../curriculum.md)

**Объём:** 2 ак. ч. (90 минут). Работа обязательна на базовом уровне. Подготовка — 15 мин; реализация/эксперимент — 40; негативные случаи — 25; анализ и оформление — 10. Образы и модели организатор готовит заранее; время скачивания сюда не входит.

## Задача и результат

Локализовать сбой среды и доказать весь путь до вычисления на GPU.

## Перед началом

Теория 2, разделы 1–2. PowerShell, Docker Desktop с WSL2 backend и разрешённый NVIDIA-драйвер; обновления системы выполняются по правилам предприятия.

Для автономного выполнения используйте [учебный комплект и инструкции запуска](../../../practice-kit/README.md). Команды выполняются в **PowerShell из каталога `materials/practice-kit`**. Свои изменения/результаты храните в `work/p2-1-preflight-and-gpu/`, сохраняя исходники эталона. Используйте [шаблон отчёта](../../../practice-kit/templates/report.md) и [протокол оценки](../../../practice-kit/templates/protocol.md).

## Исходные данные

`scripts/preflight.ps1`, эталонный ПК с RTX 3060 12 ГБ, затем GPU-контейнер комплекта.

## Порядок самостоятельного выполнения

1. Из корня комплекта выполните preflight. Запишите Windows/WSL, Docker context, версии клиента/сервера/Compose и драйвера. Сохраните лог после удаления лишних идентификаторов машины.

2. Проверьте `docker run --gpus all ... nvidia-smi`. При ошибке установите слой: нет GPU на хосте, не работает WSL passthrough, другой Docker context, несовместимый контейнер. Не устанавливайте Linux-драйвер внутри WSL по обычному Linux-рецепту.

3. В GPU-образе выполните tensor CUDA и синхронизацию. Сопоставьте torch.version.cuda и driver capability; версия из nvidia-smi не означает установленный toolkit приложения.

4. Запустите небольшую локальную модель, readiness, один запрос и benchmark. Снимите VRAM до загрузки, после и на длинном запросе; отделите PyTorch allocated/reserved от всей занятой памяти GPU.

5. Составьте runbook для двух реальных/смоделированных отказов: симптом, слой, безопасная диагностика, восстановление и повторная проверка. Сохраните ограничения 12 ГБ и резерв.

## Команды для воспроизводимого старта

```powershell
.\scripts\preflight.ps1
docker run --rm --gpus all course-gpu:2026-11 python -c "import torch; x=torch.ones(256,256,device='cuda'); print((x@x).sum().item()); torch.cuda.synchronize(); print(torch.cuda.get_device_name(0))"
```

Команды запускают эталонные компоненты/измерения. Скопируйте результаты из `work/` в каталог своего прогона до повторного запуска. Это инженерная проверка поведения, а не автоматическая сдача задания.

## Негативные случаи

Проверьте отсутствие одной диагностической программы в тестовой сессии: скрипт должен записать отказ конкретной команды и завершиться с ненулевым кодом. Старый `$LASTEXITCODE` предыдущего вызова не подтверждает успех. После контейнерного `nvidia-smi` обязательны tensor CUDA, загрузка модели, API и оценка.

Неверный context; GPU не запрошена; модель превышает доступную память. Ошибку не скрывать переводом на CPU без маркировки.

## Самопроверка и критерии приёмки

автоматический диагностический скрипт и лог подтверждают версии и `docker run --gpus all nvidia-smi`; известные ограничения и способ восстановления описаны.

Для каждого пункта укажите артефакт/строку результата в [листе ручного review](../../../practice-kit/templates/review.md): выполнено / требуется исправить / недостаточно данных. Пороги фиксируются до финального теста по риску и baseline; демонстрационные числа не являются нормами предприятия. Все ошибки и отрицательные результаты остаются в отчёте.

Почему сообщение ready после загрузки модели не гарантирует, что backward или длинный запрос поместятся в память?

## Что представить для сверки

диагностический скрипт и очищенный лог, tensor/API результаты, таблица VRAM и `runbook.md`.

Укажите версии кода/конфигурации/модели/данных, происхождение выборки, baseline, ограничения, негативные результаты и индивидуальный вклад. Для неприменимой метрики напишите причину, не ставьте ноль. Результат проверяет человек; исправление и повторное review допускаются.

## Если результат не получается

Команда preflight проверяет существующий образ. Если его ещё нет, организатор заранее загружает утверждённый образ. Успешный nvidia-smi без tensor/model/API не завершает preflight.

Сохраните минимальный синтетический пример, определите слой сбоя и повторите один случай. Не меняйте сразу модель, данные и порог: иначе причина останется неизвестной. Недоступная корпоративная зависимость остаётся явным пробелом проверки.
