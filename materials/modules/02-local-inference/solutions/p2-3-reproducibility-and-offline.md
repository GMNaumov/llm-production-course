# Эталон П2.3. Воспроизводимость и офлайн-запуск

[Задание](../practice/p2-3-reproducibility-and-offline.md) · [Теория](../self-study.md) · [Правила сверки](../../../practice-kit/README.md)

Эталон показывает один корректный вариант и границы вывода. Сначала выполните собственную попытку; затем сравните поведение, методику и причины расхождений. Код и таблицы не оценивают работу участника автоматически.

## Разбор решения

Успешный протокол содержит исполнителя, среду, время, checksums, команды и исходы. Офлайн-образ и модель — разные артефакты; нужны оба. Установка пакетов при запуске означает неполный выпуск.

Секреты не копируют в bundle: новый локальный токен допустим для учебной симуляции. Корпоративный provider/ротация проверяются отдельно. Повторный запуск проверяет устойчивость, но независимый первый запуск остаётся главным доказательством.

## Как сравнить собственный результат

1. Сопоставьте артефакты с каждым критерием [программы](../../../../curriculum.md) и задания. Укажите доказательство.
2. Разберите хотя бы одно расхождение: методика, набор/версия, ошибка кода, неопределённость или ожидание. Не подгоняйте финальный test под эталон.
3. Подтвердите негативные случаи: Отсутствует tokenizer/config; снимок содержит ссылку на личный cache; digest образа другой; на чистой машине нет UI-образа. До доукомплектования соответствующая часть не воспроизводится.
4. Зафиксируйте ограничения: В internal-сети контейнеры общаются друг с другом, но загрузка моделей в ней невозможна. Скачивания выполняют заранее в отдельном подготовительном контейнере. docker save не включает модели/volumes.
5. Передайте отчёт на ручное review. При одиночном прохождении независимая проверка остаётся ожидающей коллегу/преподавателя; собственная сверка её не заменяет.

## Пример артефакта для сверки

| Артефакт | Проверка |
|---|---|
| Образ | docker load; ID/digest |
| Веса/config/tokenizer/template | Полный snapshot и checksums |
| Код/prompt/schema/policy | Версия и manifest |
| Data/index/adapter | Snapshot либо явно null |
| Зависимости | Внутри проверенного образа, freeze приложен |
| Секреты | Отсутствуют в bundle, provision заново |
| Воспроизведение | Другой исполнитель, без pull/build/личного cache |

OFFLINE_MODE не заменяет наблюдение egress. Docker save не включает volumes.

## Контрольный вопрос

Как отличить настоящий офлайн-запуск от запуска, который случайно использовал личный cache?

Итог — аргументированное решение на измеренных данных. Latency/VRAM/стоимость зависят от среды и состава случаев; открытые синтетические результаты не обещают качество предприятия.
