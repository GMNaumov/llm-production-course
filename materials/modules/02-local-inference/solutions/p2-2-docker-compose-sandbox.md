# Эталон П2.2. Docker Compose стенд

[Задание](../practice/p2-2-docker-compose-sandbox.md) · [Теория](../self-study.md) · [Правила сверки](../../../practice-kit/README.md)

Эталон показывает один корректный вариант и границы вывода. Сначала выполните собственную попытку; затем сравните поведение, методику и причины расхождений. Код и таблицы не оценивают работу участника автоматически.

## Разбор решения

Эталон сети и контрактов дан в Compose. Gateway допускает search/rag, ограничивает вход и нагрузку; model_server принимает реализованные поля чата и возвращает usage/local_metrics. /ready gateway может вернуть 503 при доступном /live и работающем search.

NF4 сравнивается с FP16 по всем попыткам. Вывод «нет статистически различимого изменения на N случаях» допустим; «квантование без потерь вообще» недопустим. Digest/образ и модельный manifest сохраняются вместе. UI — средство наблюдения, отчёты benchmark — воспроизводимый измерительный путь.

## Как сравнить собственный результат

1. Сопоставьте артефакты с каждым критерием [программы](../../../../curriculum.md) и задания. Укажите доказательство.
2. Разберите хотя бы одно расхождение: методика, набор/версия, ошибка кода, неопределённость или ожидание. Не подгоняйте финальный test под эталон.
3. Подтвердите негативные случаи: Нет файла токена; неверный токен; модель остановлена; больше 2048 суммарных токенов; UI пытается использовать неподдерживаемый streaming/tools. Результаты должны быть контролируемыми.
4. Зафиксируйте ограничения: У учебного сервера нет streaming, tool API и constrained JSON. В UI отключите streaming либо используйте benchmark для измерений. Запуск контейнера running не равен readiness. Не публикуйте inference в сеть ради исправления UI.
5. Передайте отчёт на ручное review. При одиночном прохождении независимая проверка остаётся ожидающей коллегу/преподавателя; собственная сверка её не заменяет.
