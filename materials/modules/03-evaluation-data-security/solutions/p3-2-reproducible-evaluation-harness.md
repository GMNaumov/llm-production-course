# Эталон П3.2. Воспроизводимый контур оценки

[Задание](../practice/p3-2-reproducible-evaluation-harness.md) · [Теория](../self-study.md) · [Правила сверки](../../../practice-kit/README.md)

Эталон показывает один корректный вариант и границы вывода. Сначала выполните собственную попытку; затем сравните поведение, методику и причины расхождений. Код и таблицы не оценивают работу участника автоматически.

## Разбор решения

Для C,B,A: Recall@2=0,5; RR=0,5; nDCG@3≈0,693426. Для пустого relevant Recall/nDCG неопределённы, безответные случаи остаются в end-to-end таблице.

Эталон bias-отчёта содержит human label, judge A/B, judge B/A, стиль, совпадение и причину расхождения. Результат судьи не является единственным основанием по критичному допуску, ACL или действию. Отказ от ненужного LLM-судьи должен сопровождаться достаточной человеческой проверкой.

## Как сравнить собственный результат

1. Сопоставьте артефакты с каждым критерием [программы](../../../../curriculum.md) и задания. Укажите доказательство.
2. Разберите хотя бы одно расхождение: методика, набор/версия, ошибка кода, неопределённость или ожидание. Не подгоняйте финальный test под эталон.
3. Подтвердите негативные случаи: Пустой набор, NaN, пропущенное измерение, перефразированный неверный ответ, перестановка порядка. Неизвестное не превращается в успешный результат.
4. Зафиксируйте ограничения: Если перестановка ответов меняет оценку судьи, report должен показать нестабильность, а не усреднить её незаметно. Судья не проверяет реальное отсутствие записи/утечки.
5. Передайте отчёт на ручное review. При одиночном прохождении независимая проверка остаётся ожидающей коллегу/преподавателя; собственная сверка её не заменяет.

## Контрольный вопрос

Почему удаление таймаутов из accuracy делает контур оценки недостоверным?

Итог — аргументированное решение на измеренных данных. Latency/VRAM/стоимость зависят от среды и состава случаев; открытые синтетические результаты не обещают качество предприятия.
