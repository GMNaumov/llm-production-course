# Эталон П3.3. Threat model и безопасный отказ

[Задание](../practice/p3-3-threat-model-and-safe-refusal.md) · [Теория](../self-study.md) · [Правила сверки](../../../practice-kit/README.md)

Эталон показывает один корректный вариант и границы вывода. Сначала выполните собственную попытку; затем сравните поведение, методику и причины расхождений. Код и таблицы не оценивают работу участника автоматически.

## Разбор решения

Граница ACL находится до retrieval/rerank; роль устанавливается сервером. Tool проверяет аргументы и права независимо от диспетчера. В эталоне write отсутствует в разрешённых моделируемых вызовах, а отдельный preview/confirm работает только с человеческим подтверждением.

Эталон доказательства: до quantity=10/version=1; preview без подтверждения не меняет состояние; подтверждённый эффект даёт 12/version=2; replay после нового соединения оставляет version=2. Это проверка локальной транзакции, не гарантия распределённого PDM.

## Как сравнить собственный результат

1. Сопоставьте артефакты с каждым критерием [программы](../../../../curriculum.md) и задания. Укажите доказательство.
2. Разберите хотя бы одно расхождение: методика, набор/версия, ошибка кода, неопределённость или ожидание. Не подгоняйте финальный test под эталон.
3. Подтвердите негативные случаи: Документ требует раскрыть B; tool output предлагает write; модель подставляет actor=admin; запрос не содержит подтверждения. Приложение не принимает текст за полномочие.
4. Зафиксируйте ограничения: Фильтрация финального ответа запаздывает, если закрытый текст уже передан модели. Используйте синтетическую canary, реальные секреты для проверки утечек не нужны.
5. Передайте отчёт на ручное review. При одиночном прохождении независимая проверка остаётся ожидающей коллегу/преподавателя; собственная сверка её не заменяет.

## Пример артефакта для сверки

| Угроза | Контроль вне промпта | Доказательство | Учебный owner |
|---|---|---|---|
| A читает B | Scope до retrieval | Candidate/context IDs A | Инженер поиска |
| Tool output просит write | Allowlist/auth | Нет вызова/эффекта | Интегратор |
| Подмена preview | Actor/payload/version/expiry | Conflict без изменения | Интегратор |
| Poisoning редакции | Доверенный ingestion | Корректная active revision | Владелец данных |
| Утечка audit | Allowlist до экспорта | Нет body/token/canary | ИБ в учебной роли |

Роль упражнения не означает назначенного владельца предприятия. Для высокого риска нужны repro, наблюдение и retest.

## Контрольный вопрос

Как доказать отсутствие неподтверждённого действия, если ответ модели говорит «я ничего не изменял»?

Итог — аргументированное решение на измеренных данных. Latency/VRAM/стоимость зависят от среды и состава случаев; открытые синтетические результаты не обещают качество предприятия.
